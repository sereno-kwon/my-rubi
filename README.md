# My Rubi (my.rubiworkshop.com) 설치 안내

구조: GitHub Pages 정적 페이지(바탕화면 + 앱) → Google Apps Script 웹앱 → Google Drive(기존 고객 폴더) + `00_My Rubi Index` 시트

직원은 아이디·비밀번호로 로그인합니다. 계정은 Index 시트의 `사용자` 탭에 있고, 비밀번호는 해시로만 저장됩니다.

## 1. Apps Script 배포 (10분)

1. Drive에서 `00_My Rubi Index` 시트를 엽니다.
2. 메뉴 **확장 프로그램 → Apps Script** 를 열고, 기본 `Code.gs` 내용을 지운 뒤 `apps-script/Code.gs` 내용을 통째로 붙여넣고 **저장(⌘S)** 합니다. 저장해야 함수 목록이 나타납니다.
3. 상단 함수 선택 드롭다운에서 `test_list` 를 골라 **▷ 실행** 합니다. 처음 한 번 권한 승인 창이 뜨면 "권한 검토 → 계정 선택 → 고급 → (안전하지 않음)으로 이동 → 허용" 순서로 진행합니다. 아래 실행 로그에 Index 앞 3건이 찍히면 정상입니다.
4. **배포 → 새 배포 → 유형 선택(톱니) → 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자** (로그인 세션으로 보호됩니다)
   - 배포 후 나오는 `https://script.google.com/macros/s/…/exec` URL을 복사합니다.
5. 리포지토리의 `config.js` 에 그 URL을 넣고 커밋합니다. (`API_URL: 'https://script.google.com/macros/s/…/exec'`) 이렇게 하면 직원은 서버 주소 없이 로그인만 하면 됩니다.

> 코드를 고친 뒤에는 **배포 → 배포 관리 → (연필) → 버전: 새 버전 → 배포** 로 올려야 같은 URL에 반영됩니다.

## 2. 포털 페이지 배포

1. GitHub `sereno-kwon/my-rubi` → Settings → Pages → Source: **main / root**.
2. DNS에서 `my.rubiworkshop.com` CNAME → `sereno-kwon.github.io` (다른 브랜드 사이트와 같은 방식).

## 3. 첫 로그인

- 관리자 계정 `sereno` 가 임시 비밀번호로 만들어져 있습니다. 첫 로그인 때 새 비밀번호로 바꾸게 됩니다.
- 임시 비밀번호를 잃어버렸으면 Apps Script 편집기에서 `사용자` 탭의 sereno 행을 지우고 `setupAdmin` 함수를 실행하세요. 실행 로그에 `admin` 계정의 임시 비밀번호가 찍힙니다.

## 4. 직원 계정 관리 (관리자)

바탕화면 **사용자 관리** 앱(또는 우상단 이름 메뉴 → 사용자 관리):

- **계정 추가**: 아이디·이름·권한(직원/관리자) → 임시 비밀번호가 한 번 표시됩니다. 직원에게 전달하면 첫 로그인 때 본인이 바꿉니다.
- **비밀번호 초기화**: 새 임시 비밀번호 발급, 그 사람의 로그인 중인 세션은 모두 종료됩니다.
- **비활성**: 퇴사자 등. 즉시 로그아웃되고 다시 로그인할 수 없습니다. 기록(담당자 이름)은 그대로 남습니다.
- 권한: **직원**은 상담 현황·신규 상담 사용, **관리자**는 여기에 사용자 관리와 서버 주소 설정이 추가됩니다.

보안 규칙
- 비밀번호 8자 이상, 5회 틀리면 10분 잠금
- 로그인 유지: 체크하면 30일, 아니면 12시간 (`CONFIG.SESSION_HOURS*` 에서 조정)
- 상담 기록의 담당자·작성자는 로그인한 사람 이름으로 자동 기록됩니다

## 5. 사용 흐름

- **신규 상담**: 브랜드·고객명·모델 입력 → Index에 행 추가. "Drive 폴더 생성" 체크 시 `Customer History_브랜드/YYYYMMDD_고객명_브랜드_모델` 폴더와 `00_Log_…` 시트(브랜드 템플릿 복사), `Customer Pack`, `Internal Reference` 폴더가 함께 생깁니다.
- **상담 기록 추가**: Index 시트의 `상담 기록` 탭에 한 줄씩 쌓입니다.
- **단계 진행**: Index 단계·날짜 갱신. 계약금·예약금·출고 단계에서 금액을 넣으면 Log 마스터 탭 결제 표에 행이 추가되고, 마스터 탭이 `계약금(YYMMDD)` 식으로 스냅샷 복제됩니다.
- 문의 단계로만 등록한 건이 상담 이상으로 넘어가면 그때 폴더가 자동 생성됩니다.

## 6. Index 시트 직접 편집

Index 시트는 그대로 열어서 고쳐도 됩니다. 포털은 매번 시트를 읽으므로 수정이 바로 반영됩니다.
백필된 112건은 `메모`에 "자동 백필: 단계 확인 필요"가 들어 있습니다. 90일 넘은 건은 `출고`, 최근 건은 `상담`으로 넣어두었으니 실제와 다른 건만 `현재 단계` 열을 고쳐 주세요.
`사용자` 탭의 해시·솔트 열은 숨겨져 있습니다. 직접 고치지 말고 사용자 관리 앱을 쓰세요.

## 7. 보안 메모

- 포털에는 Index 시트 내용(고객명·모델·단계)만 올라갑니다. Log 시트의 원가·계좌번호는 링크로만 연결되고 포털에 표시되지 않습니다.
- Index 시트·고객 폴더 링크는 구글 계정 권한을 따로 따릅니다. 직원 구글 계정에 Drive 공유가 되어 있어야 열립니다.
- 고객 로그인 화면(2차)은 별도 고객 계정 탭과 고객용 읽기 전용 엔드포인트(사양·단계만)를 추가하는 방식으로 확장할 수 있습니다.

## 파일

- `apps-script/Code.gs` 백엔드 (로그인·세션·사용자 관리 포함)
- `config.js` 서버 주소 (배포 후 1회 입력)
- `lib.js` 공용 로그인·API 호출
- `index.html` 바탕화면 런처 + 로그인 화면. 앱 추가는 파일 상단 `APPS` 배열에 한 줄 (`admin:true` 면 관리자에게만 보임)
- `consult/index.html` 상담 현황 앱
- `users/index.html` 사용자 관리 앱 (관리자)
- `CNAME`
- `tools/backfill.py` 기존 폴더명 → Index 행 변환 스크립트 (이미 1회 실행해 Index를 채움)
