# My Rubi × 이카운트 재고 조회

포털의 **재고 확인** 앱에서 품목 이름·코드·바코드로 찾고, 고르면 그 순간의 이카운트 창고별 재고를 보여 주는 설정입니다. 처음 화면 검색창에 단어를 넣으면 "이카운트 재고에서 찾기" 줄도 함께 나옵니다.

```
포털(my.rubiworkshop.com) ──HTTPS──▶ DSM 역방향 프록시 ──▶ rubi-stock 컨테이너(127.0.0.1:8790) ──▶ 이카운트 OpenAPI
```

- 이카운트 API는 등록한 사무실 IP에서만 부를 수 있어서, 같은 회선의 NAS가 대신 부릅니다. API 인증키는 NAS의 `stock.env` 에만 있고 브라우저로 가지 않습니다.
- 포털에 구글 계정으로 로그인한 직원만 쓸 수 있습니다. 서비스가 포털 세션을 Apps Script에 확인합니다.
- 조회만 합니다. 이 서비스는 이카운트에 아무것도 쓰지 않습니다.
- ecount-sync 와 따로 도는 컨테이너라 한쪽을 멈추거나 고쳐도 다른 쪽에 영향이 없습니다.

## 이카운트 호출 제한과 이 서비스의 방식

이카운트 OpenAPI는 API마다 호출 간격 제한이 있고(로그인·목록 조회 10분에 1회, 단건 조회 1초에 1회), 오류가 한 시간에 30번 이어지면 막힙니다. 같은 회사 계정을 쓰는 ecount-sync 가 막히지 않도록 이렇게 동작합니다.

| 무엇을 | 언제 | 이카운트 API |
|---|---|---|
| 품목 목록(이름·규격·바코드) | 하루 한 번, 아침 7시 이후 첫 확인 때. 포털에서 수동으로 다시 받기도 가능(10분 간격) | 품목조회 (목록) |
| 창고별 재고 | 품목을 고를 때마다, 그 품목 하나만. 같은 품목은 30초 동안 다시 묻지 않음 | 창고별재고현황 (단건) |
| 로그인 | 세션이 끝났을 때만. 세션은 `data/state.json` 에 두어 재시작해도 다시 씀 | 로그인 |

- 이카운트 오류가 5번 이어지면 10분 쉬고, 하루 호출은 `DAILY_LIMIT`(기본 1000)을 넘지 않습니다.
- 검색은 NAS에 받아 둔 품목 목록에서 하므로 이카운트를 부르지 않습니다. 오늘 새로 등록한 품목이 검색에 안 나오면 재고 확인 창 아래 **품목 목록 다시 받기**를 누르거나, 품목코드를 그대로 넣고 **코드로 바로 조회**를 쓰면 됩니다.

### 인증키는 따로 받는 것을 권장

로그인 간격 제한이 사용자 ID 단위로 걸린다면, 이 서비스와 ecount-sync 가 같은 ID를 쓸 때 서로의 로그인을 막을 수 있습니다. 이카운트에서 이 서비스용 ERP 사용자(예: `STOCK`)를 하나 만들어 **재고·품목 조회 권한만** 주고, 그 ID로 API 인증키를 받아 쓰는 것이 가장 안전합니다. 조회 전용이라 키가 새어도 전표를 건드릴 수 없습니다. 같은 ID를 써도 동작은 하지만, ecount-sync 로그에 로그인 제한 오류가 보이면 ID를 나눠 주세요.

## NAS 설정 (DSM 7, 20분)

1. **폴더 만들기**: File Station에서 `docker` 공유 폴더 안에 `rubi-stock` 폴더를 만들고(ecount-sync 와 나란히), 그 안에 빈 `data` 폴더도 하나 만듭니다.
2. **파일 올리기**: `stock.py`, `docker-compose.yml`, `stock.env` 세 개를 `rubi-stock` 폴더에 올립니다. `stock.env` 는 저장소의 `stock.env.example` 을 이름만 바꾼 파일이고, 그대로 올려도 됩니다.
   - 이카운트 회사코드·사용자 ID·인증키·존은 **ecount-sync 폴더의 설정 파일에서 자동으로 읽습니다.** `docker-compose.yml` 이 옆 폴더 `../ecount-sync` 를 읽기 전용으로 붙이고, 서비스가 그 안의 `.env`, `*.env`, `config*.json` 에서 이카운트 값을 찾습니다(이름이 `COM_CODE`, `ECOUNT_COM_CODE`, `API_CERT_KEY` 처럼 조금 달라도 알아봄). ecount-sync 쪽 파일은 건드리지 않습니다.
   - ecount-sync 폴더가 `docker/ecount-sync` 가 아니면 `docker-compose.yml` 의 `../ecount-sync` 를 실제 위치로 고칩니다.
   - 조회 전용 사용자로 인증키를 따로 받았다면 `stock.env` 의 `ECOUNT_` 줄에 적습니다. 적은 값이 우선입니다.
   - `PORTAL_API_URL` 은 미리 채워져 있습니다 (포털 `config.js` 의 `API_URL`)
3. **컨테이너 띄우기**: Container Manager → 프로젝트 → 생성 → 프로젝트 이름 `rubi-stock`, 경로 `docker/rubi-stock`, 원본 **기존 docker-compose.yml 사용** → 다음 → 완료. 처음엔 `python:3.12-slim` 이미지를 받느라 1–2분 걸립니다.
4. **로그 확인**: 프로젝트 → rubi-stock → 로그에 아래 줄들이 보이면 이카운트 연결이 된 것입니다. 값은 로그에 남지 않고 어느 파일의 어느 이름에서 가져왔는지만 나옵니다.
   ```
   이카운트 값을 ecount-sync 설정에서 가져옴: .env:COM_CODE, .env:USER_ID, …
   이카운트 로그인
   품목 목록 1234개 받음
   ```
   `이카운트 API 주소가 맞지 않습니다` 가 보이면 `stock.py` 위쪽 `EP_PRODUCTS`, `EP_STOCK_ONE` 경로를 이카운트 OpenAPI 문서(자기설정 → OpenAPI)의 이름과 맞춰 주세요.
5. **역방향 프록시**: 제어판 → 로그인 포털 → 고급 → 역방향 프록시 → 생성
   - 이름 `myrubi-stock`
   - 소스: 프로토콜 **HTTPS**, 호스트 이름 **`stock.rubibase.synology.me`**, 포트 **443**
   - 대상: 프로토콜 **HTTP**, 호스트 이름 **`localhost`**, 포트 **8790**
   - Synology DDNS는 하위 이름도 같은 NAS로 오므로 DNS 설정은 따로 없습니다.
6. **인증서**: 제어판 → 보안 → 인증서 → 설정에서 `stock.rubibase.synology.me` 에 `*.rubibase.synology.me` 가 들어간 인증서를 지정합니다. NAS 앱 설치 때([`../README.md`](../README.md) 6번) 와일드카드 인증서를 받아 두었다면 고르기만 하면 됩니다.
7. **확인**: 브라우저로 `https://stock.rubibase.synology.me:8443/health` 를 열어 `{"ok": true, "service": "my-rubi-stock"}` 가 보이고 자물쇠에 경고가 없으면 끝입니다.

공유기 포트 포워딩은 NAS 앱과 같은 규칙(공용 8443 → NAS 443)을 그대로 씁니다. 역방향 프록시가 NAS 443에서 이름(`stock.`)으로 나눠 받으므로 공유기에 추가할 것이 없고, 주소에 `:8443` 이 붙습니다.

## 포털 설정

`config.js` 에 한 줄을 넣고 커밋합니다.

```js
STOCK_API: 'https://stock.rubibase.synology.me:8443/',
```

## 고치거나 업데이트할 때

- `stock.py` 를 새 버전으로 바꿔 올린 뒤 Container Manager에서 프로젝트를 **다시 시작**하면 됩니다. 세션과 품목 목록은 `data/` 폴더에 남아 있어 재시작해도 이카운트에 다시 로그인하지 않습니다.
- `stock.env` 를 바꿨다면 프로젝트를 **중지 → 빌드(또는 정리 후 시작)** 해야 새 값이 들어갑니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 재고 창에 "재고 서버에 연결할 수 없습니다" | 7번 확인 주소가 열리는지, 역방향 프록시 대상 포트 8790, 컨테이너가 실행 중인지 |
| "포털 로그인을 확인할 수 없습니다" | `stock.env` 의 `PORTAL_API_URL` 이 포털 `config.js` 의 `API_URL` 과 같은지 |
| "이카운트 로그인 실패" | 인증키·사용자 ID, 그리고 이카운트 API IP 등록에 사무실 회선이 들어 있는지 |
| "이카운트 로그인은 10분에 한 번만 됩니다" | 방금 재시작했거나 세션이 끝난 직후입니다. 10분 뒤 다시 |
| "오류가 이어져 잠시 쉬는 중" | 컨테이너 로그에서 바로 앞 오류를 확인. 10분 뒤 자동으로 다시 시도 |
| 품목은 나오는데 재고가 모두 0 | 그 품목에 창고 재고가 없거나, `MAIN_WH` 창고 코드가 다름 (기본 RLD) |
